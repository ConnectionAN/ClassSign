# 學費袋：有效清單與作廢紀錄

本次依使用者要求將已作廢學費袋移至獨立紀錄區，避免與草稿及已繳費學費袋混淆。延續已授權的 Phase 1 正式站更新；未進入報表精修。

## 顯示規則

- 預設「有效學費袋」：只顯示草稿、已開立、部分收款及已結清。原狀態篩選仍可用。
- 「作廢紀錄」：只顯示 state=void 的學費袋。月份與學生搜尋同時適用於兩區，按鈕數量為符合目前月份／搜尋的資料筆數。
- 作廢 RPC 成功且重新載入後，清除目前明細並提示已移至紀錄；只有進入「作廢紀錄」才可再查看該學費袋。作廢失敗則保留原學費袋與狀態，不顯示成功提示。
- 作廢明細顯示原費用及付款紀錄，並從既有帳務稽核資料顯示原因、時間與經手帳號；沒有新增任何資料庫欄位。
- 作廢學費袋仍可列印，不能正式開立、增加費用或登記收款。原本有收款不能直接作廢的規則保持不變。
- 切換分類會清除選取與狀態篩選，避免另一區的明細殘留。從既有外部入口開啟作廢學費袋時，自動選擇作廢紀錄分類。
- 同月份重新產生草稿後，自動回到有效學費袋並選取新草稿，舊作廢紀錄保持獨立。

## 範圍

src/Billing.tsx 與 src/visual-refresh.css 的展示及選取狀態。preview.ts 的記憶體模擬 API 補上作廢稽核與重新產生草稿；正式後端沒有更動。無 schema、RLS、RPC、migration、帳務運算或正式資料刪除。

## 驗證

- TypeScript / Vite build 通過。
- npm test：既有 59 項功能測試。
- 新增三項 UI 工作流程：手機／桌面作廢移動、原因／明細保留、已繳費保護、鍵盤操作、月份／姓名篩選、列印、重新產生草稿與重新進入頁面；以及 RPC 失敗不誤移動。
- 更新原八尺寸視覺測試，使作廢狀態從獨立分類開啟；其他四種狀態留在有效清單。保留原無溢出、月份邊界、鍵盤焦點及對比檢查。
- 以 Chromium 及 WebKit 測試，後者為 Windows 自動化環境，非實際 iPhone。
- 測試全部使用模擬 API，不操作正式學生／學費袋。
